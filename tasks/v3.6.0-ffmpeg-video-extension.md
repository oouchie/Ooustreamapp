# v3.6.0 — FFmpeg Video Extension (Drop libVLC)

## Goal
Replace the libVLC secondary player backend with a Media3 FFmpeg **video** decoder extension running inside the same ExoPlayer instance. Single engine. No backend swap. No crash guard. No JNI class-stripping issues.

## Why
- libVLC has been a constant source of bugs: ProGuard stripping JNI classes (v3.5.11 root cause), native SIGSEGV risk, dual-backend state management, crash guard complexity
- The FFmpeg video extension follows the EXACT same pattern as the existing Jellyfin FFmpeg audio extension (which works perfectly) — hardware first, software fallback
- IPTV Smarters (competitor) uses this pattern (IJKPlayer = single FFmpeg engine) and doesn't have our class of bugs

## Architecture (before → after)

### Before (v3.5.11)
```
ExoPlayer (primary) ──→ MediaCodec (HW) ──→ video
                    ──→ FFmpeg audio ext ──→ AC3/DTS/EAC3
                    ──→ ChannelMixingAudioProcessor ──→ stereo

libVLC (secondary)  ──→ activated via swapToVlcInPlace()
                    ──→ when ExoPlayer can't decode content
                    ──→ separate player engine, separate controls wiring
                    ──→ ~800 lines of swap/guard/recovery code
```

### After (v3.6.0)
```
ExoPlayer (only)    ──→ MediaCodec (HW) ──→ video (most content)
                    ──→ FFmpeg video ext ──→ HEVC Main 10, edge-case AVC,
                    │                       VC-1, MPEG-2 (software fallback)
                    ──→ FFmpeg audio ext ──→ AC3/DTS/EAC3 (existing)
                    ──→ ChannelMixingAudioProcessor ──→ stereo
```

One player. One track selector. One set of controls. `EXTENSION_RENDERER_MODE_ON` = hardware first, FFmpeg for anything hardware can't handle. Same pattern as audio.

## Estimated APK size change
- Remove: `libvlc-all:3.5.1` native .so (~15-18MB across ABIs)
- Add: self-built FFmpeg .so with video+audio decoders (~8-12MB per ABI)
- Net: roughly neutral or slight decrease (~5-10MB savings)
- Use ABI splits to avoid shipping both ABIs in one APK

## License compliance (LGPL)
- All enabled FFmpeg decoders are LGPL-licensed (no GPL codecs)
- Must provide source (link to upstream FFmpeg release tag is sufficient)
- Dynamic linking (.so files) satisfies LGPL relinking requirement
- Document FFmpeg version in Settings → About screen

## Risk areas
1. **Media3 1.2.1 is old** — PR #1591 targets newer versions. May need to backport or upgrade Media3.
2. **Combined audio+video FFmpeg build** — must not break the existing audio pipeline. Test AC3/EAC3/DTS thoroughly.
3. **MultiView (4 players)** — each player has its own FFmpeg renderer instance. Memory budget may tighten.
4. **HEVC Main 10 on AFTSS (900MB)** — FFmpeg software HEVC at any resolution is CPU-bound on Cortex-A53. Need graceful UX (v3.5.9's friendly error dialog) even after migration.
